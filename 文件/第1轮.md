开发一个 Android 原生 LLM 对话应用，Kotlin + Jetpack Compose，纯本地运行（仅 API 调用联网）。按以下顺序逐项完成，每完成一项我验证后再进行下一项。不要一次性做多项。

### 第 1 步：多模块骨架 + Navigation
- 创建模块：:app、:core:domain、:core:data、:core:network、:feature:chat。
- :app 只做组装和 @HiltAndroidApp。
- :feature:chat 创建 ChatScreen 和空 ViewModel。
- Navigation Compose 中注册 chat 路由。
- 依赖：compose-bom、navigation-compose、hilt、kotlinx-coroutines。

### 第 2 步：OpenAI 兼容流式对话（手写 OkHttp SSE）
- :core:network 中实现 OkHttp SSE 客户端：POST /v1/chat/completions，stream: true，解析 `data:` 行中的 delta.content，以 Kotlin Flow<String> 发射。
- 处理 `data: [DONE]` 终止符。
- :core:domain 定义 ChatRepository 接口（返回 Flow<String>）。
- :core:data 实现 ChatRepositoryImpl，用 Hilt @Binds 绑定。
- :feature:chat ViewModel 注入 ChatRepository，ChatScreen 展示流式内容。
- 依赖：okhttp、kotlinx-serialization-json。

### 第 3 步：Room 用量监控（两张表，面向扩展）
- :core:data 中创建 Room 数据库。
- token_usage_records 表：每次请求一行，字段包含 sessionId、model、promptTokens、completionTokens、timestamp。
- token_stats_models 表：按 model 聚合，用 @Query 的 SUM 维护，不手动累加。
- API 返回的 usage 字段（stream_options.include_usage: true）写入 records 表；聚合查询从 stats 表读取。
- ChatScreen 底部显示本次会话累计 token。
- 依赖：room-runtime、room-ktx、room-compiler（KSP）。

### 第 4 步：上下文压缩（滑动窗口，纯本地）
- :core:domain 中定义 ContextWindow 值对象，包含 maxTokens 和 compressThreshold。
- :core:data 实现 SlidingWindowManager：在发送请求前，估算历史消息 token 数，超过阈值时从列表头部移除最旧消息，直到回到安全线以内。
- 压缩逻辑不得调用额外 LLM。
- 阈值从 DataStore 读取，默认 maxTokens=80000、compressThreshold=0.9。
- 在 ChatViewModel 中接入，确保流式对话不受压缩影响。

### 第 5 步：系统提示词配置（DataStore）
- :core:data 中创建 SettingsStore（DataStore Preferences）。
- 保存 systemPrompt（String）和 model（String）两个键。
- ChatScreen 增加一个简单的设置入口（可以是 TopAppBar 的 action），进入后有一个 TextField 编辑 systemPrompt、一个只读/简单选择器显示 model。
- 每次发送请求时从 SettingsStore 读取，附加到 payload 的 system 字段和 model 字段。
- 不要手写完整的模型下拉选择器，先用 TextField 存 model 字符串即可。

### 第 6 步：现代风格 UI 收尾（Compose Material 3）
- 在现有界面上应用 Material 3 的 design tokens，不引入第三方 UI 库。
- 消息内容区最大宽度 720dp，消息间距 12dp，对话轮次间距 24dp。
- 输入框圆角 4dp，消息气泡圆角 8dp。
- 加载态使用 Skeleton（简单的占位 Composable），保持布局稳定。
- 滚动条使用 Compose 默认行为，不额外定制。
- 最终效果：干净、紧凑、符合 Material 3 规范。

### 全局纪律（每一步适用）
- 每次只引入当前步骤需要的文件。
- 新增任何跨模块依赖前，先判断是否应该走 :core:domain 接口。
- 新增持久化字段前，先判断是否应该加 @Entity 而不是塞进 DataStore。
- 每步完成后列出验证方式（例如：curl 确认 SSE 返回；Logcat 确认 token 写入 Room）。
