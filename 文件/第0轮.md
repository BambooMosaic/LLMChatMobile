### 第 1 步：环境检查
依次执行并报告结果：
- java -version（确认 JDK 21 可用）
- echo $JAVA_HOME（确认指向 JDK 21；如果为空，告诉我应该设成什么）
- which gradle || gradle -v（报告是否已有 Gradle；没有也没关系，后续会用 Wrapper）
- uname -s（区分 Windows/macOS/Linux，后续命令按平台调整）

### 第 2 步：安装 Android SDK 命令行工具（不装 Android Studio）
1. 告诉我当前系统对应的 cmdline-tools 官方下载链接（developer.android.com 的 "command-line tools only" 页面）。
2. 下载后解压到一个统一的 SDK 根目录，例如 ~/android-sdk（Windows 用 %USERPROFILE%\android-sdk）。
3. 目录结构必须调整为：~/android-sdk/cmdline-tools/latest/bin/sdkmanager（官方要求，放错位置 sdkmanager 会报错）。
4. 设置环境变量（写入 shell 配置文件，不要只临时 export）：
   - ANDROID_HOME=~/android-sdk
   - 将 $ANDROID_HOME/cmdline-tools/latest/bin 和 $ANDROID_HOME/platform-tools 加入 PATH
5. 验证：source 配置文件后，执行 sdkmanager --version，应返回版本号。

### 第 3 步：用 sdkmanager 安装构建组件
执行 sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0"，并接受许可（echo y | sdkmanager --licenses）。
验证：sdkmanager --list_installed 中能看到上述三个组件。

### 第 4 步：生成 Gradle Wrapper（不依赖 Android Studio）
1. 在项目根目录执行 gradle init --type basic --dsl kotlin（如果已有 Gradle 安装）；如果没有 Gradle，告诉我最简单的安装方式（优先 SDKMAN! 或 Homebrew）。
2. 然后执行 gradle wrapper --gradle-version 8.12（或你确认与 JDK 21/AGP 兼容的版本）。
3. 验证：项目根目录出现 gradlew、gradlew.bat 和 gradle/wrapper/gradle-wrapper.properties，且 ./gradlew --version 成功输出版本。

### 第 5 步：配置依赖版本目录（libs.versions.toml）
在 gradle/libs.versions.toml 中写入以下版本锚点（不要发散）：
[versions]
kotlin = "2.2.20"
ksp = "2.2.20-2.0.4"   # 前缀必须与 kotlin 完全一致
agp = "8.7.3"           # 与 JDK 21 / Gradle 8.12 兼容的稳定线
composeBom = "2026.09.00"
hilt = "2.57.1"
room = "2.8.5"
navigation = "2.10.2"
okhttp = "5.3.2"
serialization = "1.9.0"
coroutines = "1.10.2"

[plugins] 和 [libraries] 先搭好骨架，把上述版本引用进去，依赖项可以后续按需添加。
验证：./gradlew help 不报版本冲突。

### 第 6 步：安装 claude-android-ninja Skill
执行：npx secure-skills-cli add drjacky/claude-android-ninja/claude-android-ninja
（如果 npx 不可用，告诉我替代命令。）
验证：Skill 目录中出现 claude-android-ninja，且 Agent 能读取到它的 SKILL.md。

### 第 7 步：最终冒烟验证
执行 ./gradlew tasks，确认构建系统能正常启动。报告最终环境摘要：JDK 版本、SDK 路径、Gradle 版本、KSP 版本、Skill 是否就绪。
